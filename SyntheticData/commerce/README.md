# 커머스 합성 웹페이지

쇼핑몰 페이지를 흉내 낸 합성 데이터입니다. 무역 문서(`../trading`)가 YAML 정답과 PDF 렌더 결과의 짝이듯, 여기는 YAML 정답과 HTML 렌더 결과의 짝입니다.

```
generate_commerce_pages.py   시드 고정 생성기 (표준 라이브러리 + PyYAML)
input_yamls/<page_id>.yaml   페이지 정답. 필드 이름은 bias.json 스키마 이름
output_html/<page_id>.html   렌더 결과. 파이프라인에 그대로 넣습니다
manifest.yaml                페이지 목록 (분할 · 쇼핑몰 · 테마 · 언어 · 유형 · URL)
queries.yaml                 자연어 질의와 정답 레코드 키
records.yaml                 레코드 정답 (검색 평가의 정답 키가 가리키는 대상)
```

다시 만들 때는 `python generate_commerce_pages.py`, 저장된 파일과 같은지만 볼 때는 `--check` 를 씁니다. 시드가 고정이라 항상 같은 파일이 나옵니다.

## 페이지 구성

쇼핑몰 6곳 × 페이지 24장 = 144장. 쇼핑몰마다 주문 · 상품 · 배송의 목록 2장과 상세 4장, 리뷰 · 쿠폰 · 이벤트의 목록과 상세 1장씩입니다.

| 분할 | 쇼핑몰 | 언어 | 테마 | 구조 |
|---|---|---|---|---|
| dev | 하늘상점 | ko | `admin_twin` | 관리자 표. 레코드 하나가 `<tr>` 두 개 |
| dev | 모아몰 | ko | `admin_grid` | ARIA 역할과 해시 CSS 클래스뿐인 div 그리드 |
| dev | 숲속잡화 | ko | `store_cards` | 구매자 카드. 대부분의 값에 라벨 없음 |
| dev | Harbor & Pine | en | `admin_flat` | 한 행에 한 레코드인 관리자 표 |
| test | 뚝배기마켓 | ko | `mobile_dl` | 모바일 `dl/dt/dd` |
| test | Blue Lantern Supply | en | `store_sections` | 응답형 표, `section/strong` 상세 |

**test 는 튜닝에 쓰지 않습니다.** 쇼핑몰도 테마도 dev 와 겹치지 않으므로, 개선을 고른 뒤 처음 보는 레이아웃으로 확인하는 데만 씁니다.

## 일부러 넣은 함정

- 상태 필터 탭과 검색 폼의 상태 어휘, 건수 숫자
- 푸터의 회사 주소 · 전화번호 (주문자 · 수령인 주소와 헷갈리는 자리)
- 구매자 화면 상세의 추천 상품 (다른 상품 이름과 가격, 반복 구조)
- 주문 상세의 상품 표 (상세 페이지에도 행이 반복되는 표가 있음)
- `<br>` 로 끊긴 주소 (낱말 경계가 태그에만 있음)
- 적립금 · 쿠폰할인 같은 스키마 밖 숫자 열, 배송 페이지의 주문번호 열
- 주문자와 수령인이 다른 주문, `외 N건` 이 붙은 대표 상품명
- `input` · `textarea` 안에 든 값 (`admin_twin` 상세)
- 날짜 · 금액 표기가 쇼핑몰마다 다름 (`26.07.07`, `2026년 7월 7일`, `₩29,900`, `$12.50`)

## 만들 때 지킨 것

- 앵커 어휘를 베끼지 않습니다. `bias.json` 예시에 있는 브랜드 · 택배사 · 카드사 이름은 쓰지 않습니다. 그래야 임베딩이 맞힌 것과 문자열이 맞은 것을 구분할 수 있습니다.
- 실제 회사 · 상표를 쓰지 않습니다. 도메인은 예약 TLD `.test` 만 씁니다. 이름 · 주소 · 전화번호는 무작위 조합입니다.
- 정답은 세계에서 계산합니다. 상태 · 기간 · 금액 질의의 정답은 조건을 만족하는 레코드 전체이고, 사람이 고른 예시가 아닙니다.
